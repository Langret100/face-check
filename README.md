# AI 표정 친구 v24 — FHD 미축소 · 심층 점검·가상 부하 검증

GitHub Pages에서 실행하는 웹캠 기반 3D 캐릭터 프로그램입니다. 별도의 계정/서버로 영상이나 음성을 업로드하지 않습니다. 다람쥐(Mr Squirrel, CC0)와 사람형(AvatarSample A, **CC0 아님**)을 설정에서 선택할 수 있습니다. 라이선스는 `ASSET_LICENSES.md`를 확인하세요.

## 이번 수정에서 실제로 고친 문제

- **상황별 음성이 나오지 않던 원인 수정:** 이전에는 카메라 시작 시 마이크 음성 따라하기가 자동 실행되었고, `voiceSay()`가 마이크 켜짐만으로 모든 상황별 TTS를 차단했습니다. 이제 마이크 기능과 상황별 TTS가 함께 작동하며, TTS가 재생되는 동안에는 마이크 자동녹음 감지를 잠시 멈춰 자기 목소리를 되받아 녹음하지 않습니다.
- **대화 상황 확장 및 지속 시간 검증:** 처음 만났을 때(안정적으로 0.68초 인식한 뒤), 오랫동안 자리를 비웠다 다시 들어왔을 때, 손을 일정 시간 올렸을 때, 웃음/부정적 표정/놀람을 유지했을 때 각 캐릭터의 다른 멘트를 말합니다. 재생·오류·중단 상태는 정리하고 대사 남발을 방지합니다.
- **음성 구분:** 사람형은 설치된 여성형 한국어 음성을 우선 선택하고 높은 피치(1.72)·여린 음색의 마이크 변조를 적용합니다. 다람쥐는 카툰식 높은 피치(1.96), 빠른 속도, 과장된 음색의 마이크 변조 및 코믹한 대사를 사용합니다. TTS의 실제 음색은 웨일북에 설치된 한국어 음성 엔진에 따라 달라질 수 있습니다.
- **좌우 거울 동작:** 원본 카메라 프레임은 MediaPipe에 그대로 입력, 웹캠 미리보기 및 3D 화면만 CSS에서 좌우 반전합니다. 관절 목표 x 좌표는 다시 반전하지 않게 통일했습니다. 두 모델의 좌우 팔 뼈를 검증했으며, 같은 모델을 재선택할 때 누적 회전되는 문제를 방지하도록 초기 자세 복원을 추가했습니다.
- **FHD 출력 유지:** 가로 최대 1920×1080, 세로 최대 1080×1920 렌더링 상한을 유지합니다. FPS에 따른 동적 해상도 저하나 70% 축소 기능은 **추가하지 않았습니다.** 출력 영역이 더 작으면 그 영역의 네이티브 화면 픽셀 수를 사용합니다. 입력 웹캠 권장 해상도도 기존 480×360에서 **1280×720**으로 높였습니다(실제 크기는 기기 협상).
- **코드·CPU 최적화:** MediaPipe는 가능하면 Worker에서 실행합니다. 478점 얼굴 랜드마크 전체가 아닌 필요한 점 3개·표정 채널 20개·상체 관절 8개만 Worker 밖으로 보내 전송/객체 할당을 줄였습니다. 캐릭터 하위 트리의 강제 월드 행렬 갱신은 새 포즈 입력에만 수행합니다. 팔 관절의 방향 해석도 매 60fps 프레임마다 수행하지 않고 **새 포즈 추론 결과가 도착할 때만** 수행하고 나머지 프레임은 캐시 목표로 부드럽게 보간합니다. 마이크 음성 감지는 매 렌더 프레임이 아닌 32ms 주기로 처리합니다. 반복 객체 생성도 일부 제거했고, 카메라 재연결 시 오래된 Worker 응답은 무시합니다.

## 배포

ZIP 압축을 풀고 **폴더 안의 전체 내용을** GitHub 저장소 루트에 반영하세요. GitHub Actions의 `Deploy AI Expression Friend`가 `npm install → npm run check → npm test → npm run build`를 실행하고 필요한 Three.js, MediaPipe WASM 및 AI 모델 파일을 다운로드하여 `dist`를 배포합니다. 이 소스 ZIP을 그대로 `index.html`만 클릭해서 열면 `vendor/`가 없으므로 동작하지 않습니다. HTTPS로 배포해야 카메라·마이크 접근이 가능합니다.

## 검사

- `npm run check`: JavaScript 구문 검사
- `npm test`: **23개 검사**. 사람형/다람쥐 음성 선택, 상황별 인사/감정/손 들기, 마이크+TTS 병행, 좌우 좌표 및 실제 VRM 팔 본 방향, FHD 미축소 규칙, 3,600회 60Hz 합성 렌더 호출, 900개 720p 합성 프레임 Worker, 카메라 재연결과 캐릭터 전환 경합 검사
- `npm run build`: 종속 패키지와 공식 AI 모델을 받아 오프라인 실행이 가능한 사이트 생성 (빌드에는 네트워크 필요)

자세한 변경 이유와 시험 항목은 `검증결과.md`에 기록했습니다.

**실기기 60fps 보장에 관하여:** 웨일북의 GPU, 브라우저, 모니터 주사율, 동시 실행 앱에 따라 결과가 달라집니다. 이 파일은 60fps를 *목표*로 코드 수준의 병목을 줄였지만, 이 환경에서는 웹캠/마이크/배포용 종속 파일을 통한 실기기 측정이 불가능해 실제 60fps를 검증했다고 주장하지 않습니다. 배포 뒤 캐릭터 양쪽을 각각 1~2분씩 화면 우하단 FPS 표시와 함께 테스트하세요. FPS는 JavaScript 애니메이션 프레임의 측정치로 GPU 성능 프로파일링과는 다릅니다.


## v24 · 표정/목/거울 반응 정확성 수정 (2026-11-23)

- **실제 수정 1:** 기존 얼굴 추적은 좌우 회전(yaw)과 기울기(roll)만 2D 얼굴 점으로 근사했고, 목 앞뒤 기울기(pitch)는 추적하지 않았음. MediaPipe 공식 얼굴 4×4 변환행렬 출력(`outputFacialTransformationMatrixes`)을 Worker와 메인 스레드 폴백 양쪽에서 활성화. 3D 피치·요·롤을 추출하고 안전한 각도로 제한하여 머리/목뼈에 분배 적용.
- **실제 수정 2:** 카메라가 처음 얼굴을 인식하면 기존 대기 모션(yaw/roll/pitch/웃음)이 추적 목표값에 매 렌더 프레임 반복 누적되어 실제 움직임을 반대로 만들 수 있었음. 매 프레임 재사용하는 별도의 `renderTarget`을 도입하고, 인식값 `target`은 갱신 시에만 변경되도록 수정.
- **검증:** `npm test` 32개 통과. 고개 위/아래/좌우, 눈 깜박임+웃음 동시 반응, 팔 한쪽 들기, 좌우 미러 좌표, 60Hz 가상 3,600프레임 중 인식값 무누적, Worker 4×4행렬 전달 등 검사.
- **미변경:** FHD 가로 1920×1080/세로 1080×1920 출력 상한, 720p 카메라 요청, 두 VRM 원본, 기존 화면, 서버 업로드 없음.
- **한계:** 테스트는 합성 MediaPipe 결과와 렌더 호출의 가상 실행이다. 실제 웨일북 GPU, 실제 카메라 영상과 사람 얼굴에서 완전한 60fps 및 관절의 자연스러움은 기기에서 확인해야 한다.
